# Как править ah-skills

Это проектный harness для Codex. Источник навыков и вспомогательных инструкций — `domains/`; установщик и проверки — `tools/`. Корневые документы описывают текущий интерфейс и меняются вместе с ним.

## Один источник правды

Правь исходники в `domains/`, а не установленные копии в `.agents/`. CLI экспортирует навыки, правила и инструкции ролей в `.agents/` целевого проекта как снимки. После изменения исходников выполни установку повторно; даже без `--copy` изменения не появляются в уже установленном навыке автоматически. Хук `test_gate.py` устанавливается симлинком, а `.codex/hooks.json` — копией.

```bash
go build -o ah-skills ./tools
./ah-skills install domains code core git --project .
./ah-skills doctor --project .
```

`install` не создаёт целевой `AGENTS.md`; для него есть `$code-init`. Не удаляй `.agents/` или `.codex/` целиком: там могут находиться файлы проекта. Подробнее — в `AGENTS.md` и `tools/README.md`.

## SKILL.md и README.md — разные документы

`SKILL.md` — инструкция Codex с фронтматтером `name` и `description`, алгоритмом, границами и ссылками на нужные ресурсы. Пиши точно и кратко: модель читает его при использовании навыка.

`README.md` рядом — объяснение для человека: назначение навыка, условия применения и пример. Не дублируй в нём полный промпт.

## Добавление навыка

1. Создай `domains/<домен>/skills/<имя>/SKILL.md` с фронтматтером `name` и `description`. Имя каталога и значение `name` должны совпадать; имя обычно имеет префикс домена.
2. Добавь `README.md` и нужные ресурсы. Ссылки на правила и роли пиши относительно корня целевого проекта: `.agents/rules/` и `.agents/agents/`.
3. Если навык обращается к роли, добавь или обнови файл в `domains/<домен>/agents/`. Это инструкция для делегирования, а не автоматически зарегистрированный тип агента.
4. Обнови таблицу доменов в корневом `README.md` и карту компонентов в `AGENTS.md`.
5. Собери CLI и запусти проверки:

   ```bash
   go build -o ah-skills ./tools
   ./ah-skills check
   go test ./...
   ```

6. Повтори установку в тестовый проект и проверь `ah-skills doctor --project <path>`. Для навыка с хуком проверь `.codex/hooks.json` и доверие к проектному хуку в Codex.

`description` определяет, когда навык уместен. Пиши конкретные пользовательские запросы и различай пересекающиеся навыки. В примерах вызова используй синтаксис Codex `$имя`.

## Добавление домена

1. Создай `domains/<имя>/manifest.yaml` с `name`, `description` и `requires_env`. Папки `skills/`, `rules/`, `agents/`, `hooks/` добавляй по потребности.
2. Проверь, что установленный ресурс работает из `.agents/` целевого проекта. Вспомогательные правила и роли должны читаться навыком явно.
3. Обнови `README.md`, `AGENTS.md` и нужные проверки установщика.

`requires_env` и `requires_bin` ограничивают установку: `install all` пропускает недоступный домен с предупреждением, а явный запрос завершает ошибкой. У текущих доменов таких требований нет.

## Правила качества

- Числа и результаты тестов бери из реальных прогонов.
- Не объявляй вспомогательные `.agents/agents/` и `.agents/rules/` нативными автоматически загружаемыми компонентами Codex.
- Запись в предсказуемый путь должна отказываться от небезопасных симлинков и не перетирать чужой файл без явного `--force`.
- Хук `code` должен проверять состояние тестов по факту. После изменения тестового файла он разрешает остановку только после успешной полной тестовой команды в текущем ходе; ошибки проверки нельзя описывать как fail-open.
- Сохраняй краткий, проверяемый контракт вывода ролей. Соблюдай их read-only или файловые ограничения.
- Не меняй production напрямую: для DevOps действует GitOps через ArgoCD.

## Чужие навыки и Git

Чужой навык не вендорится в `domains/` без решения о лицензии и сопровождении. Заимствованную идею атрибутируй в соседнем `README.md`; текст не копируй дословно.

Коммиты оформляются по `domains/git/rules/git-conventions.md`. Не выполняй push, tag, merge или публикацию без явного разрешения.
