# ah-skills CLI

Go installer для проектных навыков Codex. Сборка из корня репозитория:

```bash
go build -o ah-skills ./tools
```

## Команды

| Команда | Действие |
|---|---|
| `ah-skills list [domains|skills]` | Показать доступное |
| `ah-skills install all --project PATH` | Установить все домены |
| `ah-skills install domain NAME --project PATH` | Установить домен |
| `ah-skills install domains NAME... --project PATH` | Установить несколько доменов |
| `ah-skills install skill NAME --project PATH` | Установить один навык и ресурсы его домена |
| `ah-skills status --project PATH` | Показать lockfile и состояние |
| `ah-skills doctor --project PATH` | Проверить missing, drifted и untracked файлы |
| `ah-skills uninstall domain|domains|all|skill ... --project PATH` | Удалить только отслеживаемые файлы |
| `ah-skills check` | Проверить manifest и `SKILL.md` |

`--project` по умолчанию равен текущему каталогу. `--harness-root` указывает каталог этой копии, если команда запущена извне. `--dry-run` не пишет файлы. `--force` разрешает замену чужих или изменённых файлов при установке. `--copy` принят для совместимости; навыки Codex получают снимки, а хук `test_gate.py` — симлинк. `--target codex` можно указать явно, но это режим по умолчанию.

Установка пишет в `<project>/.agents/{skills,rules,agents}/` и `<project>/.agents/skills-lock.json`. `skills` вызываются в интерфейсе как `$имя` или выбираются через `/skills`. Папки `rules` и `agents` содержат вспомогательные инструкции, которые навыки читают явно. После изменения исходников повторите `install`. Для работы хука нужен `python3`. Домен `code` также ставит `.codex/hooks.json` снимком и `.codex/hooks/test_gate.py` симлинком. После установки откройте проект заново, проверьте `.codex/hooks.json` и `/hooks`, затем доверьте проект и определение хука: до этого проектные хуки Codex не выполняются. `doctor` напоминает о проверке, но не видит состояние доверия. Существующий чужой `.codex/hooks.json` сохраняется; для замены требуется `--force`.

### Тестовый хук

При первом событии каждого хода Codex хук запоминает состояние тестовых файлов как исходное. Дальше он отслеживает их создание, изменение и удаление по содержимому. Учитываются `test_*` с поддерживаемым расширением, имена вроде `*_test.go`, `*.test.ts`, `*.spec.ts`, `*Test.java`, `*Tests.java`, `*.test.cs`, а также файлы поддерживаемых языков в каталоге `tests/`. Каталоги `.git`, `.codex`, `.agents`, `node_modules`, `.venv`, `venv`, `vendor`, `target`, `dist`, `build`, `__pycache__` пропускаются. Изменения до первого события этого хода хук не обнаружит. Состояние хранится отдельно для пары `session_id` и `turn_id` во временном каталоге системы.

После изменения тестов `Stop` и `SubagentStop` блокируются, пока в том же ходе после последней правки не завершится успешно распознанная полная тестовая команда через инструмент `Bash`. Хук смотрит `PostToolUse` и требует подтверждённый код выхода `0`; сам тесты не запускает. После очередной правки нужен новый запуск. Без изменений тестов остановка разрешена. Ошибка чтения конфигурации или состояния блокирует остановку, поскольку запуск нельзя подтвердить.

Встроенные команды без дополнительных аргументов: `go test ./...`, `pytest` или `py.test`, `python -m pytest`, `npm test`, `pnpm test`, `yarn test`, `bun test` (также `run test`), `cargo test`, `mvn test`, `mvnw test`, `gradle test`, `gradlew test`, `dotnet test`. Допускаются префикс `env`, присваивания переменных окружения и путь к исполняемому файлу. Конвейеры, составные shell-команды и фильтры тестов не засчитываются. Для другого раннера создайте `.codex/test_gate.json` с точным списком аргументов, например `{"command":["make","check"]}`, до запуска тестов. Хук проверит такую команду по тем же правилам и не станет её выполнять. Он подтверждает успешный запуск команды, но не число обнаруженных тестов.

Установщик не пишет `AGENTS.md`: в открытом проекте вызовите `$code-init` для его создания или аккуратного обновления. Если ресурс не помещается в scope отдельного skill, установите домен целиком. `doctor` подходит как проверка установленного снимка.
